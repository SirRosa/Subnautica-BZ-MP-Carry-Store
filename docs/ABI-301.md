# Carry & Store — binary ABI audit (BOT Benson multiplayer 3.0.1)

Inspection performed on actual previously supplied DLL bytes, not on guessed public-source signatures. The binaries remain outside the public GitHub repository. All checks below are static metadata checks.

## Game hooks: 14 exact method matches

- `TechData.GetItemSize(TechType)`: `Vector2int` (value-type; x, y are int fields).
- `Inventory.Awake()`, `ResetInventory()`, `UpdateContainers()`, `OnProtoDeserialize(ProtoBuf.Serializer)`: void.
- `uGUI_InventoryTab.Open()`: void.
- `StorageContainer.Awake()`, `ResetContainer()`, `OnOpen()`: void.
- `StorageContainer.Resize(int,int)`: void; the component has integer `width`, `height` fields and a `container` property.
- `MapRoomFunctionality.Start()`, `OnPostRebuildGeometry(...)`, `IsAllowedToAdd(Pickupable,bool)`, `AddItem(InventoryItem)`.
- `ItemsContainer.Resize(int,int)` is a real method; `sizeX` and `sizeY` properties exist; UI `uGUI_ItemsContainer.OnResize(int,int)` also exists.

## Server hooks: 3 exact matches

- `Subnautica.Server.Core.AuthorizationProfile.Initialize(string,string)` returns AuthorizationProfile, with `InventoryItems` property.
- `Subnautica.Server.Processors.Metadata.StorageProcessor.GetStorageContainer(ConstructionItem)` returns network Metadata.StorageContainer. This is private but patchable.
- `Subnautica.Server.Processors.Metadata.BaseMapRoomProcessor.OnDataReceived(AuthorizationProfile, MetadataComponentArgs, ConstructionItem)` returns bool.

## Network model hooks: 6 method matches

- `Subnautica.Network.Models.Metadata.StorageItem.GetSizeX()` and `GetSizeY()` return byte.
- `Metadata.StorageContainer.HasRoomFor(StorageItem)` returns bool.
- Three `Metadata.StorageItem.Create` overloads return StorageItem and use byte `Size`.
- `Metadata.StorageContainer.Resize(byte,byte)`, `Create(byte,byte)`, `GetSizeX()`, `GetSizeY()` exist. Both container `Size` and item `Size` are bytes. Encoding in public source: width + height*10.

`Subnautica.API.Features.SubnauticaPlugin` has a virtual `PluginType` and the `SubnauticaPluginType` enum has `Client`, `Server`, `ServerClient`. This confirms the ABI, **not** that the 3.0.1 launcher automatically activates a ServerClient plugin on the authoritative host.

## Important qualifications

- The static check matched 20 named patch methods and three `StorageItem.Create` overloads. It did not inspect or execute the running game or prove Harmony ordering against all 3.0.1 plugins.
- `MapRoomFunctionality.IsAllowedToAdd` checks the `allowedUpgrades` type array, not `upgradeSlots`; thus a 3×3 grid does not automatically bypass the upgrade type whitelist.
- Real network packet processing, save/reload, UI clipping, concurrent transfers and rollback still require two-player gameplay validation.
- The Harmony 2.3.3 integration harness uses fake game/server objects to check patch installation, value-type result replacement, pre-validation behavior and foreign patch preservation. This is stronger than contract-only tests, but does not validate real Unity objects.

## Exact runtime target audit following v0.1.2 launcher failure (2026-11-15)

The full list of 23 named Harmony targets was compared against the metadata of the
six **actual supplied** 3.0.1 game/BOT Benson DLLs (plus all three `StorageItem.Create` overloads).
All targets exist with the declared method arity after the following correction:

- **Fixed:** `uGUI_InventoryTab.OnOpenPDA` takes **two** parameters in the actual
  `Assembly-CSharp.dll`, not zero. The 0-argument declaration in the old mock harness was wrong
  and prevented ALL hooks from being installed.
- `uGUI_InventoryTab.Open` takes zero; `uGUI_ItemsContainer.Init` takes one;
  `uGUI_ItemsContainer.Uninit` takes zero.
- Inventory/game object/storage/scanner/server/network target method names and arities were
  rechecked against the metadata; no other arity mismatches were found in the selected hooks.
- The integration harness now defines the **actual two-argument** `OnOpenPDA` and invokes
  that method through Harmony, so a wrong `/0` target fails CI before publishing a DLL.

This validates method existence and arity, **not** live Harmony execution or multiplayer behavior.
